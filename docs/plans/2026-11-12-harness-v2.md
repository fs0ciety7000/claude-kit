# Plan : harness v2 (12 nov. 2026)

Objectif : une chaîne « idée → dépôt → équipe → plan → code → CI → déploiement → docs » **légère**, identique sur
macOS, Linux et claude.ai/code, avec la CI sur le runner Forgejo auto-hébergé (le serveur de CI) et plus jamais sur GitHub
Actions. Validé par l'utilisateur le 12/11/2026 ; on avance lot par lot, chaque lot par PR.

## Constat (étude du 12/11)

- **Lourdeur** : `/new-project` = 4 validations + équipement + identité + redémarrage de session, au moins 3 agents
  opus puis un agent par tâche ; `subagent-driven-development` impose une relecture par tâche (contredit la rigueur
  proportionnée de la PR #28) ; registre, `team-builder`, `code-reviewer`, `brand-identity` (CSP) et gabarit
  `AGENTS.md` réintroduisent durcissement et relecteurs sur les petits projets.
- **Contexte permanent** : ~1 500 mots de CLAUDE.md global, ~1 200 mots de descriptions, jusqu'à 8 000 caractères de
  hook de démarrage ; Superpowers ~10 000 mots chargés presque à chaque fois ; tâches suivies à 3 endroits ;
  `kit-emit` branché sur tous les événements (2 à 3 hooks par appel d'outil).
- **Permissions** : commandes sûres non autorisées (git rebase/worktree, tofu plan, compose, plusieurs `kit …`) ;
  fusion des réglages par union (doublons, règles jamais retirées) ; hook secrets qui bloque des mots, pas des fichiers.
- **GitHub en dur** : `kit repo create`, `kit api`, Coolify par la GitHub App, toute la CI en GitHub Actions
  (quota épuisé) ; aucune mention de Forgejo dans le kit.
- **Cloud** : les sessions claude.ai/code ne clonent que depuis GitHub ; les plugins ne s'y chargent pas
  (`.claude/` du dépôt et setup script, oui).

## Décisions

| Sujet | Décision |
|---|---|
| Modèle | **Opus 5.5 partout** ; effort par rôle dans l'en-tête de l'agent, modifiable par projet (`project.yaml`) ou à la demande |
| Taille S / M / L | Règle la cérémonie, pas le modèle. **S** (vitrine, outil, prototype) : pas de relecteur, pas de CSP, CI minimale. **M** (application) : tests, CI complète, prévisualisation par PR. **L** (produit, infra, données) : relecteurs code, sécurité et QA, durcissement. Les règles lourdes sont des fichiers importés **seulement** en L |
| Équipe | Proposée à l'annonce du projet. Base : architect, devops, backend-dev, frontend-dev, brand-identity, ui-designer. Stack : creative-coder (GSAP, Three.js), rust-dev (CLI, TUI ratatui, Tauri), go-cli (binaires), pocketbase. Hors dev : researcher, copywriter, creative-content. Relecteurs en L ou sur demande |
| Exécution | Un agent par **lot**, pas par tâche ; le fil principal fait les petites choses ; pas de relecture par tâche |
| Forge | **GitHub principal** (dépôts, PR, sessions cloud). **CI uniquement sur le serveur de CI** |
| Pont GitHub → CI | **`fs0-bridge`** (Go, sur Coolify) : webhook GitHub → push vers Forgejo → Actions sur le serveur de CI → statut ✔/✘ dans la PR GitHub → déploiement Coolify si `main` vert. Jetons de déploiement et de statut dans le pont, **jamais sur le serveur de CI** |
| Sécurité de la CI | Aucune CI pour une PR de fork sans label posé par l'utilisateur (dépôts publics) |
| Dépendances | Renovate par l'application **Mend** sur GitHub |
| Docs | Le coffre de notes actuel est abandonné. Nouveau hub **`atlas`** (Starlight), derrière **Access et sur le tailnet** : une page par projet (installation, dépannage, décisions, avancement généré depuis `plan.md`), index et catalogue des services (URL publiques et noms du tailnet), leçons communes, notes par stack. Lu et écrit par Claude **sur demande**, comme un dépôt Git ; lu aussi pour réutiliser un projet ou un service existant. Contenu **écrit de zéro** (pas de reprise des docs d'infra existantes) |
| Suivi | Le dashboard **abandonné** pour l'instant (application et données gardées, sauvegardées). Validations **dans le chat**. Suivi d'une session de terminal dans claude.ai/code par `claude remote-control` |
| Cloud | Environnement « fs0 » : réseau limité à une liste d'hôtes (ajouts à la demande, approuvés par carte), secrets réseau Forgejo, Coolify, Access, Cloudflare ; setup script qui installe le kit ; mêmes commandes qu'en local |
| Ajouts | `/ship` (CI → déploiement → test de fumée → lien), `/retire` (DNS, Access, Coolify, sondes), prévisualisation par PR (web M/L), dépôts modèles par stack (templates GitHub), `kit doctor` (même version du kit partout) |
| Outils du chantier | `plugin-dev` (officiel Anthropic), `skill-creator`, `fewer-permission-prompts` ; `skill-reviewer` (trailofbits) et `claude-code-sessions` (davila7) relus avant toute installation |

Stacks courantes : Astro, Go (web et binaires), Next, React/Vue (Vite), PocketBase, GSAP ; Rust (CLI, TUI, Tauri) ;
parfois hors développement.
